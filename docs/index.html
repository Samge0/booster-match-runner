Booster Match Runner

Booster Studio 的侧边面板，用于在两个智能体之间运行 3v3 机器人足球比赛（红方 vs 蓝方），支持实时比分、关键事件时间轴、无头运行和自动比赛记录归档。

核心功能

全面的比赛管理工具，从智能体选择到记录归档，一切尽在掌握

双智能体对战

从运行的模拟容器和/或本地 .agent 文件中选择两个智能体（红方 vs 蓝方）

两种运行模式

启动可视化比赛或无头模式运行，灵活适应不同需求

实时比分追踪

每 3 秒轮询一次比分和比赛时间，自动检测比赛结束

关键事件时间轴

进球、犯规、定位球等事件从 events.jsonl 增量读取

自动保存与导出

每场比赛自动归档，支持导出为 CSV 格式，方便数据分析

视频录制

UI 模式下可将每场比赛录制为 MP4，精确保存视觉呈现

智能体上传

直接上传 .agent 包到容器，支持自定义 ID/名称部署

智能体管理

列出并删除所有智能体，包含确认提示防止误操作

弹性恢复

在 Booster Studio 窗口重新加载/重新打开后自动恢复比赛状态

常见问题

快速了解常见问题的解答

系统要求是什么？
  • Booster Studio ≥ 1.9.10
  • Docker 可在主机 CLI 访问（docker 在 PATH 中）
  • virtual-robot sim 容器正在运行
  • 主机 PATH 中需要 ffmpeg（仅用于视频录制）
如何首次设置？
  1. 在 Booster Studio 左侧活动栏打开 ROBOTS → 选择 Virtual robot 创建/启动 Docker 容器
  2. 点击右上角的 Run 按钮。Booster Studio 会将完整的 3v3 比赛栈部署到容器中
  3. 一旦 football3v3_runner 存在且端口 38383 开始监听，扩展就准备好了
如何安装扩展？

有三种安装方式：

  • 扩展市场（推荐）：在 Booster Studio 的扩展视图中搜索"Booster Match Runner"并点击安装
  • 从发布版本安装：下载 .vsix 文件，通过命令面板或 CLI 命令安装
  • 从源代码构建：运行 npm install、npm run compile 并使用 vsce 打包
比赛记录保存在哪里？

所有比赛记录自动归档到 ~/.booster-match-runner/matches/ 目录，每个比赛包含摘要、事件日志和运行日志。失败的比赛会保存在 ~/.booster-match-runner/matches-failure/ 中。
